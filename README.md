# 나의 기록 공간

모든 페이지 상단에서 블루·보라·주황 색상과 라이트·다크 모드를 각각 선택할 수 있습니다. 선택은 브라우저에 저장되어 페이지 이동과 새로고침 후에도 유지됩니다. 기본 색상은 블루이며 밝기를 직접 선택하기 전에는 기기 설정을 따릅니다.

개인과 회사의 계획을 순서대로 연결하고, 반복하는 루틴과 매일 배운 내용을 한곳에서 관리하는 웹앱입니다.

**[웹사이트 바로가기](https://swdynamics.github.io/to_do_list/)**

## 주요 기능

| 기능 | 설명 | 접속 |
| --- | --- | --- |
| 연결 리스트 계획 | 개인·회사 계획을 구분하고, 여러 할 일을 순서대로 연결해 관리합니다. | [계획 열기](https://swdynamics.github.io/to_do_list/plan/) |
| 삭제 내역 | 삭제한 라인의 이름·생성 시각·내용을 개인·회사별 텍스트 기록으로 보관합니다. | 계획 탭에서 오른쪽 스와이프 또는 ‘삭제 내역’ 선택 |
| 루틴 저장소 | 반복하는 작업 순서를 루틴으로 저장하고 새 계획으로 불러옵니다. | 계획 페이지에서 이용 |
| TIL (Today I Learned) | 배운 내용과 생각을 제목·분류·날짜와 함께 기록합니다. | [TIL 열기](https://swdynamics.github.io/to_do_list/learning/) |
| 계정과 동기화 | 로그인한 계정의 데이터를 Supabase에 저장하고 다른 기기에서 불러옵니다. | [로그인](https://swdynamics.github.io/to_do_list/auth/) |

로그인하지 않으면 현재 브라우저에 데이터를 저장합니다. 다른 브라우저나 기기에서 같은 기록을 사용하려면 웹사이트에 같은 계정으로 로그인하고 동기화 상태를 확인하세요.

라인 제목 아래의 ‘이름 수정’으로 이름을 변경할 수 있습니다. 새 라인의 생성 시각은 수정 후에도 유지되며 삭제 내역에 표시됩니다. 생성 시각을 저장하지 않았던 기존 라인은 ‘생성 시각 미기록’으로 표시합니다.

삭제 내역은 이 기능이 추가된 이후 삭제한 라인부터 남습니다. 라인 전체 삭제 시 현재 항목들을 보관하며, 마지막 항목을 삭제해 라인이 사라질 때도 해당 내용을 보관합니다. 내역 화면에서 왼쪽으로 밀거나 ‘현재 계획으로 돌아가기’를 누르면 계획 목록으로 돌아옵니다. 라인 안의 가로 스크롤은 기존처럼 사용할 수 있습니다. 삭제 내역은 기존 계획 데이터와 함께 저장되어 별도의 DB 마이그레이션이 필요하지 않습니다.

## 사용 방법

1. 웹사이트에 접속해 계획 또는 TIL 메뉴를 선택합니다.
2. 계획 페이지에서 개인·회사 탭을 선택하고, 작업을 한 줄씩 입력해 계획을 만듭니다. 반복할 작업은 루틴으로 저장해 다시 사용할 수 있습니다.
3. TIL 페이지에서 배운 내용과 생각을 기록합니다.
4. 기기 간 동기화가 필요하면 로그인합니다.

## 기술 구성

- 화면과 기능: HTML, CSS, JavaScript
- 인증과 데이터 저장: Supabase Auth, PostgreSQL
- 비로그인 데이터 저장: 브라우저 localStorage
- 웹 호스팅: GitHub Pages

## 로컬 실행

별도의 빌드 과정 없이 정적 웹 서버로 실행합니다. Python이 설치되어 있다면 프로젝트 루트에서 다음 명령을 실행하세요.

```bash
python -m http.server 5500
```

환경에 따라 `python` 대신 `python3`를 사용합니다. 서버가 실행 중인 상태에서 [http://localhost:5500/](http://localhost:5500/)에 접속하세요.

Python이 없다면 VS Code의 Live Server 확장으로 `index.html`을 열어 미리 볼 수도 있습니다. 로컬 주소와 공개 사이트의 브라우저 저장 공간은 서로 분리됩니다.

### TIL 데스크·아카이브

기존 기록과 새 기록은 데스크에 표시됩니다. 기록 상단의 ‘아카이브로 보내기’로 보관하고, 아카이브 탭에서 ‘데스크로 보내기’로 다시 꺼낼 수 있습니다. 이동과 수정은 해당 목록의 맨 위에 반영되며, 수정만으로 보관 위치가 바뀌지는 않습니다. 위치는 각 기록의 `location` (`desk` / `archive`) 필드로 기존 데이터와 함께 저장합니다. 필드가 없는 기존 기록은 데스크로 읽으며 별도 SQL 작업은 필요 없습니다. 자동 복습 일정과 문제 풀이는 아직 구현하지 않았습니다.

### TIL 카테고리

카테고리는 자유롭게 입력하거나 입력창 아래 최대 4개의 추천에서 선택합니다. 데스크·아카이브 전체의 기존 카테고리를 정확 일치 → 접두어 → 포함 순으로 추천하고, 같은 조건에서는 기록 수가 많은 이름을 먼저 표시합니다. 방향키·Enter 선택과 Escape 닫기를 지원합니다. 앞뒤·연속 공백과 대소문자 차이는 같은 카테고리로 처리하며, 빈 값은 미분류입니다. 각 보관 위치에서 제목·내용을 검색하고, 전체·카테고리·미분류 버튼을 눌러 결과를 좁힐 수 있습니다. 버튼의 숫자는 현재 검색 결과 수이며, 데스크·아카이브 탭의 숫자는 각 위치의 전체 기록 수입니다.

### TIL 서식 편집기

Tiptap으로 제목, 목록, 체크리스트, 들여쓰기, 인용, 표, 코드 블록을 편집할 수 있습니다. 붙여넣기 메뉴의 기본값은 HTML 서식 유지이며, 일반 텍스트만 들어오면 마크다운 문법을 감지합니다. 원하는 결과와 다르면 ‘마크다운으로 변환’ 또는 ‘일반 텍스트’를 선택한 뒤 붙여넣으세요. 제목은 접을 수 있는 목차에도 표시됩니다. 글자를 선택한 뒤 도구 모음의 추천 색상 6가지(파랑·초록·청록·주황·빨강·보라)를 적용하거나 ‘기본색’으로 되돌릴 수 있습니다. 색상은 라이트·다크 테마에 맞춰 밝기가 조정되며 저장 후에도 유지됩니다. 이미지 첨부와 수식 렌더링은 지원하지 않습니다.

기존 일반 텍스트 기록은 그대로 표시합니다. 새로 저장한 기록은 기존 `content` 텍스트에 더해 `contentFormat: "tiptap-v1"`, `richContent` JSON을 함께 보관하며, 기존 Supabase `learning` 데이터에 저장하므로 SQL 변경은 필요 없습니다. 이전 버전의 앱으로 같은 기록을 수정하면 서식 정보가 사라질 수 있으므로, 서식 기록은 새 편집기에서 수정하세요.

편집기 번들은 저장소에 포함되어 있어 정적 서버로 바로 실행할 수 있습니다. `learning/editor.js`를 수정했다면 Node.js 환경에서 다시 빌드합니다.

```bash
npm ci
npm run build
npm test
npm run test:browser
```

브라우저 검증은 설치된 Google Chrome과 임시 로컬 서버(8766)를 사용하며, 외부 서비스 연결을 차단한 별도 브라우저 컨텍스트에서 실행됩니다. `editor.bundle.js`는 생성 파일이므로 직접 수정하지 않습니다.

## Supabase 설정

별도의 Supabase 프로젝트로 운영하려면 `shared/supabase-config.js`의 연결 정보를 설정하고 [Supabase 초기 설정 안내](supabase/README.md)에 따라 테이블과 인증 URL을 구성하세요. 인증 URL은 실제 사용하는 배포 주소와 로컬 주소에 맞춰 설정합니다.

브라우저에는 공개용 `publishable key`만 사용하며, `service_role` 키는 소스에 넣지 않습니다.
