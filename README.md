# 나의 기록 공간

모든 페이지 상단에서 블루·보라·주황 색상과 라이트·다크 모드를 각각 선택할 수 있습니다. 선택은 브라우저에 저장되어 페이지 이동과 새로고침 후에도 유지됩니다. 기본 색상은 블루이며 밝기를 직접 선택하기 전에는 기기 설정을 따릅니다.

개인과 회사의 계획을 순서대로 연결하고, 반복하는 루틴과 매일 배운 내용을 한곳에서 관리하는 웹앱입니다.

**[웹사이트 바로가기](https://swdynamics.github.io/to_do_list/)**

## 주요 기능

| 기능 | 설명 | 접속 |
| --- | --- | --- |
| 연결 리스트 계획 | 개인·회사 계획을 구분하고, 여러 할 일을 순서대로 연결해 관리합니다. | [계획 열기](https://swdynamics.github.io/to_do_list/plan/) |
| 삭제 내역 | 삭제한 라인의 이름·생성 시각·내용을 개인·회사별 텍스트 기록으로 보관합니다. | 계획 탭에서 오른쪽 스와이프 또는 ‘삭제 내역’ 선택 |
| 루틴 저장소 | 반복하는 작업 순서를 루틴으로 저장하고 새 계획으로 불러옵니다. | 계획 페이지에서 이용 |
| TIL (Today I Learned) | 배운 내용과 생각을 제목·분류·날짜와 함께 기록합니다. | [TIL 열기](https://swdynamics.github.io/to_do_list/learning/) |
| TIL 아카이브 | 충분히 익힌 기록을 별도 서재에서 검색하고 글 단위로 읽습니다. | [아카이브 열기](https://swdynamics.github.io/to_do_list/learning/archive/) |
| 계정과 동기화 | 로그인한 계정의 데이터를 Supabase에 저장하고 다른 기기에서 불러옵니다. | [로그인](https://swdynamics.github.io/to_do_list/auth/) |

로그인하지 않으면 현재 브라우저에 데이터를 저장합니다. 다른 브라우저나 기기에서 같은 기록을 사용하려면 웹사이트에 같은 계정으로 로그인하고 동기화 상태를 확인하세요.

라인 제목 아래의 ‘이름 수정’으로 이름을 변경할 수 있습니다. 새 라인의 생성 시각은 수정 후에도 유지되며 삭제 내역에 표시됩니다. 생성 시각을 저장하지 않았던 기존 라인은 ‘생성 시각 미기록’으로 표시합니다.

삭제 내역은 이 기능이 추가된 이후 삭제한 라인부터 남습니다. 라인 전체 삭제 시 현재 항목들을 보관하며, 마지막 항목을 삭제해 라인이 사라질 때도 해당 내용을 보관합니다. 내역 화면에서 왼쪽으로 밀거나 ‘현재 계획으로 돌아가기’를 누르면 계획 목록으로 돌아옵니다. 라인 안의 가로 스크롤은 기존처럼 사용할 수 있습니다. 삭제 내역은 기존 계획 데이터와 함께 저장되어 별도의 DB 마이그레이션이 필요하지 않습니다.

## 사용 방법

1. 웹사이트에 접속해 계획 또는 TIL 메뉴를 선택합니다.
2. 계획 페이지에서 개인·회사 탭을 선택하고, 작업을 한 줄씩 입력해 계획을 만듭니다. 반복할 작업은 루틴으로 저장해 다시 사용할 수 있습니다.
3. TIL 페이지에서 배운 내용과 생각을 기록합니다.
4. 기기 간 동기화가 필요하면 로그인합니다.

## 기술 구성

- 화면과 기능: HTML, CSS, JavaScript
- 인증과 데이터 저장: Supabase Auth, PostgreSQL
- 비로그인 데이터 저장: 브라우저 localStorage
- 웹 호스팅: GitHub Pages

## 로컬 실행

별도의 빌드 과정 없이 정적 웹 서버로 실행합니다. Python이 설치되어 있다면 프로젝트 루트에서 다음 명령을 실행하세요.

```bash
python -m http.server 5500
```

환경에 따라 `python` 대신 `python3`를 사용합니다. 서버가 실행 중인 상태에서 [http://localhost:5500/](http://localhost:5500/)에 접속하세요.

Python이 없다면 VS Code의 Live Server 확장으로 `index.html`을 열어 미리 볼 수도 있습니다. 로컬 주소와 공개 사이트의 브라우저 저장 공간은 서로 분리됩니다.

### TIL 데스크·북케이스·아카이브

| 공간 | 용도 | 화면 |
| --- | --- | --- |
| 데스크 | 오늘 당장 공부할 기록 | 기존 TIL의 데스크 탭 |
| 북케이스 | 정리했지만 다시 상기할 개념 | 기존 TIL의 북케이스 탭 |
| 아카이브 | 충분히 이해하여 간간이 읽을 글 | 별도 `/learning/archive/` 페이지 |

새 기록은 데스크에 표시됩니다. 데스크와 북케이스는 기존 이동 버튼을 사용하며, 어느 쪽에서도 ‘아카이브로 보내기’를 누를 수 있습니다. 데스크·북케이스에서 이동과 수정은 해당 목록의 맨 위에 반영됩니다. 제목만 수정하면 위치·복습 일정은 유지되며, 밑줄이 있는 본문을 수정하면 복습 일정과 함께 데스크로 돌아갑니다.

아카이브는 카테고리, 제목·내용 검색, 12편씩 나눈 요약 목록과 글 상세 화면으로 구성합니다. 목록에서는 본문 전체를 렌더링하지 않습니다. 글을 열면 밑줄·색상·목록·표·코드 등 원래 서식을 보여주며 빈칸 문제는 표시하지 않습니다. 글 상세에서 북케이스 또는 데스크로 다시 보낼 수 있고, ‘글 수정’은 기존 편집기로 연결합니다. 아카이브 글은 본문을 고쳐도 아카이브 위치와 복습 정보를 유지합니다. 글 주소를 복사해도 다른 사용자에게 공개되지는 않으며, 현재 계정 또는 브라우저에 저장된 기록만 읽습니다.

저장 위치는 `learning/record-data.js`의 `LOCATION.DESK` (`desk`), `LOCATION.BOOKCASE` (`bookcase`), `LOCATION.ARCHIVE` (`archive`)로 정의합니다. 탭·이동·채점·재출제 로직은 이 정의를 사용합니다. 아카이브 정렬은 아카이브로 보낸 시각을 기준으로 하며, 해당 시각이 없는 기록은 기록 날짜를 사용합니다.

로컬 `learningRecords`와 Supabase `learning` 데이터는 다음 형태로 저장합니다. DB 테이블·컬럼 변경이나 SQL 실행은 필요 없습니다.

```json
{ "version": 3, "records": [{ "id": "example", "title": "기록", "date": "2026-10-27", "content": "내용", "location": "archive" }] }
```

- 이전 로컬 배열과 서버의 `{ version: 1, records: [...] }`에 한해서 `archive`를 `bookcase`로 변환합니다. 이전 형식에서 위치가 없는 기록은 `desk`로 읽습니다.
- 버전 2의 `desk`·`bookcase`는 그대로 유지하며, 버전 3의 `archive`만 새 아카이브로 취급합니다. 버전 2에서 허용하지 않았던 `archive`는 계속 오류로 처리해 과거 값과 새 의미를 혼동하지 않습니다.
- 불러올 때 메모리에서 호환 변환하며, 다음 기록 저장·수정·이동·채점 성공 시 전체 목록을 버전 3으로 저장합니다. 단순 조회만으로 서버 데이터를 일괄 갱신하지 않습니다. 기존 기록 ID·순서·본문·서식·복습 정보와 추가 필드는 유지됩니다.
- 알 수 없는 위치, 지원하지 않는 문서 버전, 손상되거나 ID가 중복된 기록을 발견하면 데스크로 바꾸거나 제외하지 않고 저장을 차단합니다.
- 최상위 `version`은 기록 목록의 저장 형식이며, `review.version`(복습 일정 형식)과 별개입니다. 로그인 캐시는 원래 문서 버전을 포함한 채로 읽으며 서버 저장이 실패하면 기존 데이터를 유지합니다.

두 페이지는 `learning/library.js`를 통해 최신 문서에 변경한 기록만 반영합니다. 로컬은 지원 브라우저에서 Web Locks를 사용하고, 서버는 `updated_at`을 비교하는 조건부 저장으로 다른 기록의 동시 변경을 유지합니다. 같은 기록이 다른 화면에서 변경되었다면 저장을 중단하고 편집 중인 내용을 남깁니다. 저장 실패 시 기존 데이터는 유지됩니다. 배포 후에는 다른 기기와 탭도 새로고침해야 합니다. 구버전 앱의 쓰기를 DB에서 차단하는 규칙은 포함하지 않습니다.

이번 분리는 페이지와 본문 렌더링의 분리입니다. 네트워크 조회·저장은 여전히 사용자별 TIL 전체를 하나의 JSON 문서로 처리합니다. 아카이브가 크게 늘면 기록별 DB 행, 목록 요약 조회, 서버 검색·페이지 나누기를 도입해야 전송량과 저장 비용도 줄일 수 있습니다.


### TIL 카테고리

카테고리는 자유롭게 입력하거나 입력창 아래 최대 4개의 추천에서 선택합니다. 데스크·북케이스 전체의 기존 카테고리를 정확 일치 → 접두어 → 포함 순으로 추천하고, 같은 조건에서는 기록 수가 많은 이름을 먼저 표시합니다. 방향키·Enter 선택과 Escape 닫기를 지원합니다. 앞뒤·연속 공백과 대소문자 차이는 같은 카테고리로 처리하며, 빈 값은 미분류입니다. 각 보관 위치에서 제목·내용을 검색하고, 전체·카테고리·미분류 버튼을 눌러 결과를 좁힐 수 있습니다. 버튼의 숫자는 현재 검색 결과 수이며, 데스크·북케이스 탭의 숫자는 각 위치의 전체 기록 수입니다.

데스크 또는 북케이스에서 카테고리(미분류 포함)를 선택하면 ‘N개 아카이브로 보내기’로 해당 탭의 카테고리 전체를 한 번에 옮길 수 있습니다. 검색으로 숨겨진 기록도 포함하며, 이동 버튼에는 실제 대상 개수를 표시합니다. ‘전체’에서는 일괄 이동을 제공하지 않습니다. 이동 대상 기록을 수정 중이면 먼저 저장하거나 수정을 취소해야 합니다. 본문·서식·복습 정보를 유지하고 한 번에 저장하므로, 저장 실패나 다른 화면의 대상 기록 변경이 감지되면 일부만 옮겨지지 않고 일괄 이동을 중단합니다.

### TIL 서식 편집기

Tiptap으로 제목, 목록, 체크리스트, 들여쓰기, 인용, 표, 코드 블록을 편집할 수 있습니다. 붙여넣기 메뉴의 기본값은 HTML 서식 유지이며, 일반 텍스트만 들어오면 마크다운 문법을 감지합니다. 원하는 결과와 다르면 ‘마크다운으로 변환’ 또는 ‘일반 텍스트’를 선택한 뒤 붙여넣으세요. 제목은 접을 수 있는 목차에도 표시됩니다. 글자를 선택한 뒤 도구 모음의 추천 색상 6가지(파랑·초록·청록·주황·빨강·보라)를 적용하거나 ‘기본색’으로 되돌릴 수 있습니다. 색상은 라이트·다크 테마에 맞춰 밝기가 조정되며 저장 후에도 유지됩니다. 이미지 첨부와 수식 렌더링은 지원하지 않습니다.

기존 일반 텍스트 기록은 그대로 표시합니다. 새로 저장한 기록은 기존 `content` 텍스트에 더해 `contentFormat: "tiptap-v1"`, `richContent` JSON을 함께 보관하며, 기존 Supabase `learning` 데이터에 저장하므로 SQL 변경은 필요 없습니다. 이전 버전의 앱으로 같은 기록을 수정하면 서식 정보가 사라질 수 있으므로, 서식 기록은 새 편집기에서 수정하세요.

편집기 번들은 저장소에 포함되어 있어 정적 서버로 바로 실행할 수 있습니다. `learning/editor.js`를 수정했다면 Node.js 환경에서 다시 빌드합니다.

```bash
npm ci
npm run build
npm test
npm run test:browser
```

브라우저 검증은 설치된 Google Chrome과 임시 로컬 서버(8766)를 사용하며, 외부 서비스 연결을 차단한 별도 브라우저 컨텍스트에서 실행됩니다. `editor.bundle.js`는 생성 파일이므로 직접 수정하지 않습니다.

## Supabase 설정

별도의 Supabase 프로젝트로 운영하려면 `shared/supabase-config.js`의 연결 정보를 설정하고 [Supabase 초기 설정 안내](supabase/README.md)에 따라 테이블과 인증 URL을 구성하세요. 인증 URL은 실제 사용하는 배포 주소와 로컬 주소에 맞춰 설정합니다.

브라우저에는 공개용 `publishable key`만 사용하며, `service_role` 키는 소스에 넣지 않습니다.


### 밑줄 빈칸 복습

TIL 작성 도구의 ‘밑줄 · 출제’로 정답을 지정하고 ‘빈칸 미리보기’로 확인합니다. 밑줄이 있는 기록을 저장하면 30분 동안 원문을 보여주고, 이후 데스크에서 해당 부분을 빈칸으로 표시합니다. 입력하지 않았거나 공백만 입력한 빈칸도 바로 채점하며 오답으로 처리합니다. 채점 후 맞힌 빈칸의 정답은 파란색, 틀린 빈칸의 정답은 빨간색으로 표시하며 새로고침 후에도 유지됩니다. 모든 빈칸을 맞히면 북케이스로 이동합니다. 오답이면 원문과 정답을 공개하고 데스크에 유지하며, 풀이 시점부터 30분 후 다시 출제합니다. 앞뒤 공백과 한글 유니코드 표현은 정규화하지만 대소문자와 내부 공백은 구분합니다.

출제 시각과 최근 결과는 기존 기록 JSON의 `review`에 저장되므로 DB 마이그레이션은 필요하지 않습니다. 앱 종료·새로고침 후에도 일정이 유지되고, 화면 복귀 및 30초 간격으로 출제 여부를 확인합니다. 원본 richContent는 변경하지 않습니다. 데스크·북케이스 기록은 본문이나 서식이 바뀌면 출제 시각을 다시 잡고 데스크로 옮기며, 제목만 바꾸면 기존 일정이 유지됩니다. 아카이브 글 수정은 위치·복습 정보를 유지합니다. 북케이스나 아카이브에서 데스크로 가져오면 즉시 빈칸으로 다시 출제합니다. 이전 24시간 일정도 최초 기준 시점으로부터 30분 일정으로 자동 변환합니다. 기존 기록은 밑줄을 추가하고 저장하면 복습을 시작합니다.

채점 결과 저장이 실패하면 이동하지 않고 현재 화면의 답안을 유지하여 재시도할 수 있습니다. 로그인 상태의 오프라인 채점 결과는 서버 저장이 성공해야 확정됩니다. 현재 출제 판단은 기기 시각 기준이며 서버 시각 보정, 알림 발송 및 망각곡선 간격 조정은 포함하지 않습니다.


### 연결리스트 순서 변경

각 요소의 ⠿ 손잡이를 끌어 같은 라인 안에서 순서를 변경할 수 있습니다. 기존 PC 그리드와 모바일 세로 배치를 유지하며, 삽입 위치를 선으로 표시하고 화면 가장자리에서 자동으로 스크롤합니다. 손잡이에 초점을 둔 뒤 ← / → 또는 Home / End로도 이동할 수 있습니다. Escape, 터치 취소, 라인 밖에 놓기는 순서 변경을 취소합니다. 요소 수정·추가 중에는 먼저 해당 작업을 마쳐야 합니다.

순서 변경은 요소 ID·내용·완료 상태를 유지하면서 연결 순서만 바꿉니다. 저장 중에는 추가 조작을 잠시 막고, 저장 실패 시 원래 순서로 되돌립니다. 다른 라인으로 옮기는 기능은 포함하지 않습니다.
